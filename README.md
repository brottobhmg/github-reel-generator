## ✨ What is this?

This project is an **automated content pipeline** that takes a GitHub repository
URL and produces a complete, publish-ready social media reel:

- 🎙️ A **voice-over script** generated by an LLM
- 🎥 A **screen recording** of the repository page (scrolling)
- 🎬 A **final MP4** with karaoke-style subtitles synced to the audio
- 📝 A **description, title and tags** ready for TikTok / Instagram / YouTube

It is built as a **polling job system**: a Telegram bot (or any client) submits
jobs, a FastAPI backend queues them, and a worker downloads and processes them.

## 🏗️ Architecture

```
┌──────────────┐     submit job      ┌──────────────────┐
│  Telegram    │ ──────────────────▶ │   FastAPI        │
│  Bot         │                     │   Backend        │
└──────────────┘                     │   (SQLite queue) │
                                     └────────┬─────────┘
                                              │ GET /api/next-job
                                              ▼
                                     ┌──────────────────┐
                                     │   Job Runner     │
                                     │   (worker)       │
                                     └────────┬─────────┘
                                              │ download + process
                                              ▼
                                     ┌──────────────────┐
                                     │   Media Pipeline │
                                     │  (LLM + TTS +    │
                                     │   video)         │
                                     └──────────────────┘
```

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the full module breakdown
and the API contract.

## 🚀 How it works

1. A user sends a **GitHub link** to the Telegram bot (or the job is created via
   the API).
2. The pipeline **fetches the README** and searches for extra web context.
3. An LLM generates the **script, description, title and tags**.
4. **Kokoro** synthesizes the voice-over locally on CPU.
5. **Playwright** records a scrolling capture of the repository page.
6. **Groq Whisper** extracts word-level timestamps from the audio.
7. **MoviePy** composites the final reel with synced subtitles.
8. The result (video + JSON metadata) is delivered back to the user.

- **Python 3.10+**

## 🔧 Installation

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/github-reel-generator.git
cd github-reel-generator

# 2. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Install Playwright browsers
python -m playwright install --with-deps

# 5. Configure your environment
cp .env.example .env
# ... edit .env and add your API keys
```

## ⚙️ Configuration

All configuration is done through environment variables (see `.env.example`):

| Variable | Description | Required |
|----------|-------------|----------|
| `NVIDIA_NIM_API_KEY` | Nvidia NIM API key (primary LLM) | No* |
| `GROQ_API_KEY` | Groq key (Whisper transcription + fallback) | Yes |
| `OPENROUTER_API_KEY` | OpenRouter key (LLM fallback) | No* |
| `TELEGRAM_BOT_TOKEN` | Telegram bot token (from @BotFather) | For bot |
| `API_URL` | Backend polling API URL | Yes |
| `POLL_INTERVAL` | Polling interval in seconds | No |
| `LOAD_DELAY` | Page load delay during recording (s) | No |

\* At least one LLM provider key is required.

> ⚠️ **Never commit your `.env` file.** It is gitignored. Use `.env.example`
> as a template.

## ▶️ Usage

### Start the backend + bot

```bash
./start.sh
```

This starts the FastAPI server (port 8000) and the Telegram bot. Stop with:

```bash
./stop.sh
```

### Run the job runner (worker)

```bash
python job_runner.py            # poll forever
python job_runner.py --once     # process a single job and exit
python job_runner.py --debug    # debug logging + artifacts
```

### Run the Telegram bot only

```bash
python pipeline.py
```

### Debug mode

Pass `--debug` to any entry point to enable **debug logging** and generate
artifacts (logs, screenshots, guides) **only when requested**, keeping the
working tree clean during normal use.
